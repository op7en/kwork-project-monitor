# Milestone 6: VPS preparation implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan inline. The owner's task authorizes stages A–E here; approval is required at the real deployment boundary. No commits, pushes or live operations.

**Goal:** Prepare reproducible Docker operations on a separate Ubuntu 24.04 VPS while preserving the existing M5 baseline, ledger and guard.

**Architecture:** One Compose service, Node 24 Debian slim, non-root process, no published ports. Mount the complete host state directory at `/app/.local-state`. A separate deployment entry point checks existing state before importing the unchanged bot entry point; local startup remains unchanged.

**Tech Stack:** Existing TypeScript/ESM, node:sqlite, Docker Engine and Compose >=2.30.

**Spec:** Owner's Milestone 6 request in this session, AGENTS.md, docs/milestone-5.md.

## Global constraints

- No reading `.env`, live Gmail/Telegram requests, VPS access, real state transfer or baseline reset.
- Preserve the five pre-existing modified files and HANDOFF-ANTIGRAVITY.md.
- Monitoring remains OFF after every restart; no changes to M5 business logic.
- Backups require a stopped writer: SQLite plus WAL/SHM and guard form one set. Hot raw copies are unsupported.
- Never restore an older guard to bypass current high-water protection. Image rollback reuses current data.

## Review focus

- Both DB and guard missing must refuse deployment, not create a new installation.
- Dirty session or DB/guard mismatch must block transfer/start pending separately authorized maintenance.
- Wrong account/owner binding must fail before Telegram polling.
- Docker context must exclude every local/private file by default.
- Container shutdown timeout must accommodate existing network drain; forced kills need manual state investigation.
